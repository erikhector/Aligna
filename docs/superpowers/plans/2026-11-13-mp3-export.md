# MP3 Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the mix as MP3 (192/256/320 kbps CBR) as well as 16/24-bit WAV.

**Architecture:**
- LAME 3.100's encoder sources are compiled into a static `lame` target.
- A small streaming wrapper `Mp3Encoder` (in `src/io/`) feeds it float blocks.
- `exportMix` takes an `ExportSettings` and writes either WAV (unchanged path) or MP3 through the wrapper.
- LAME's own resampler handles project rates other than 32, 44.1 or 48 kHz, with output at 44.1 kHz.
- The export dialog gains a format and bitrate choice.

**Tech Stack:** C++20, JUCE 8.0.4, CMake FetchContent, LAME 3.100, Catch2.

**Spec:** `docs/superpowers/specs/2026-11-13-mp3-export-design.md`

## Global Constraints

- LAME 3.100 comes from `https://downloads.sourceforge.net/project/lame/lame/3.100/lame-3.100.tar.gz` with `URL_HASH SHA256=ddfe36cab873794038ae2c1210557ad34857a4b6bdc515785d1da9e175b1da1e`.
- Build only `libmp3lame/*.c`, plus `libmp3lame/vector/xmm_quantize_sub.c` only if needed. Do not build mpglib or the frontend. No `HAVE_MPGLIB`.
- Suppress warnings for the LAME target only. Our own code stays warning-free.
- A hand-written config header replaces autotools. It must work on MSVC, clang (macOS arm64 + x86_64 universal) and gcc. CI must stay green on all 3 OSes.
- Bitrates allowed: exactly 192, 256 and 320 kbps CBR. The default is 320.
- MP3 output is always stereo (joint stereo is fine).
- The output rate is the project rate if it is 32000, 44100 or 48000. Otherwise it is 44100.
- The ID3v2 title is the project file name without extension, or "Untitled" if unsaved.
- Existing export guards stay:
  - never write over a project source;
  - refuse while clips are stretching;
  - progress and cancel;
  - write to `<name>.tmp` and move into place, so no partial file is left on failure or cancel.
- No audio-thread work. Encoding runs on the existing export thread.

## Review Focus

1. A 96 kHz project exports a 44.1 kHz MP3 of the right duration, not a sped-up or pitched one. A test pins this.
2. Cancelling halfway leaves neither the `.mp3` nor the `.tmp` file. A test pins this.
3. The "Untitled" and odd-character project names make a valid ID3 title and don't crash. A test with "Mix ö 1" pins this.
4. Choosing MP3 but typing `song.wav` in the save box gives `song.mp3`, not a WAV-named MP3. The `withExtension` helper already exists; the dialog must use the chosen extension.
5. A very short mix (fewer samples than one MP3 frame, e.g. 100 samples) still produces a decodable file. A test pins this.

### Task 1: LAME build + Mp3Encoder

**Files:**
- Modify `CMakeLists.txt`.
- Create `third_party/lame/config.h` if needed.
- Create `src/io/Mp3Encoder.h/.cpp` and `tests/Mp3EncoderTest.cpp`.

**Interfaces — Produces:**
```cpp
namespace aligna {
class Mp3Encoder {            // not thread-safe; one export at a time
public:
    // Opens `file` for writing. outRate = inRate if in {32000,44100,48000} else 44100.
    // kbps must be 192, 256 or 320. Returns false and sets error otherwise.
    bool open(const juce::File& file, double inRate, int kbps, const juce::String& title, juce::String& error);
    bool write(const juce::AudioBuffer<float>& stereo, int numSamples, juce::String& error); // channels 0,1
    bool finish(juce::String& error);   // flush + write LAME/Xing tag + close
    ~Mp3Encoder();                      // closes without finishing if needed
    static int outputRateFor(double inRate);
};
}
```

- [ ] **Step 1: write the failing tests** (tag `[mp3]`). Each decodes the result with JUCE's `MP3AudioFormat` reader.
  - `"outputRateFor"`: 44100 → 44100, 48000 → 48000, 32000 → 32000, 96000 → 44100, 22050 → 44100.
  - `"rejects bad bitrate"`: 128 → false, with a non-empty error.
  - `"encodes 1 kHz tone"`:
    - Input: 2 s, 48 kHz, stereo, 0.5 amplitude, 320 kbps.
    - The decoded sample rate is 48000.
    - The decoded length is within ±2304 samples of 96000.
    - Zero-crossing count over the middle 1 s is 2000 ± 20.
  - `"96k input is resampled to 44.1k"`:
    - Input: 1 s at 96 kHz.
    - The decoded rate is 44100.
    - The length is within ±2304 of 44100.
  - `"tiny input"`: 100 samples produces a file the reader opens.
  - `"title tag"`:
    - Use the title "Mix ö 1".
    - The file starts with the bytes "ID3".
    - The UTF-8 title bytes or a Latin-1 form appear in the first 256 bytes.
    - It decodes fine.
- [ ] **Step 2:** Run the tests: `ctest --test-dir build -R mp3`. Expected: FAIL (compile error).
- [ ] **Step 3: FetchContent and build LAME, implement `Mp3Encoder`.**
  - FetchContent the LAME URL and hash above.
  - Add a static library target `lame_enc` from the `libmp3lame/*.c` glob, minus the files that need mpglib.
  - Set the include dirs `include/`, `libmp3lame/` and the config dir.
  - Defines: `HAVE_CONFIG_H`, `STDC_HEADERS`, `HAVE_STDINT_H`, `HAVE_ERRNO_H`, `HAVE_FCNTL_H`, `HAVE_LIMITS_H`, `ieee754_float32_t=float`, `TAKEHIRO_IEEE754_HACK` (non-MSVC). On MSVC add `_CRT_SECURE_NO_WARNINGS` and `/w`; elsewhere `-w`.
  - Link `lame_enc` PRIVATE into `aligna_core`.
  - Implement the encoder:
    - Call `lame_init`.
    - Set `in_samplerate`, `out_samplerate = outputRateFor`, `num_channels = 2`, `brate`, `VBR = vbr_off`, `quality = 2` and `write_id3tag_automatic(gfp, 0)`.
    - Call `lame_init_params`, then `id3tag_init`, `id3tag_v2_only` and `id3tag_set_title` (Latin-1 via `toStdString` of a Latin-1-safe conversion is fine, or `id3tag_set_textinfo_utf16`).
    - Write the ID3v2 bytes from `lame_get_id3v2_tag` first.
    - Then call `lame_encode_buffer_ieee_float` per block into a scratch buffer sized `1.25*n + 7200`.
    - Then `lame_encode_flush`.
    - Then rewrite the Xing frame at the tag offset via `lame_get_lametag_frame` (seek back).
    - Write through `juce::FileOutputStream`.
- [ ] **Step 4:** Run `ctest --test-dir build -R mp3`. Expected: PASS. Then run the full ctest, which must pass with output warning-free in our code.
