# Aligna v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cross-platform desktop DAW focused on editing audio clips on tracks and aligning them precisely (nudge, grid snap, automatic cross-correlation alignment).

**Architecture:** A plain-data `Project` model (no JUCE ValueTree) edited only through pure functions and a snapshot-based undo history. A `SourcePool` decodes audio files fully into memory at the project rate. An offline-testable `Mixer` renders any range of the project, and both real-time playback and WAV export use it. The JUCE UI draws from the current project, and edits go through `AppController`.

**Tech Stack:** C++20, JUCE 8.0.4 (FetchContent), Catch2 v3.7.1 (FetchContent), CMake ≥ 3.22, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-13-aligna-daw-design.md`

## Global Constraints

- License **AGPL-3.0** (JUCE 8 open-source terms). Full license text in `LICENSE`.
- Windows, macOS, Linux; CI builds and tests all three on every push. Release builds are **unsigned**.
- **No allocation, locks or file I/O on the audio thread.**
- Source audio files are **never modified**.
- Clip/timeline positions are `int64` sample counts at the project rate. The project rate is fixed at creation (default **48000**) and never rescaled.
- Overlap rule: on a track, **the later-starting clip covers the earlier one** where they overlap; no automatic crossfade; moves are never blocked.
- Mix bus is stereo; clips mono or stereo; mono clips follow track pan.
- Import formats: WAV, AIFF, FLAC, MP3 (`JUCE_USE_MP3AUDIOFORMAT=1`).
- Project file: JSON, extension `.aligna`, contains `"format": 1`, audio paths relative to the project file when possible.
- Export: WAV, 16- or 24-bit, project sample rate.
- Auto-align only shifts, never stretches. Region = timeline selection if any, else up to the first **60 s** of overlap. Default search **±30 s**, max **±5 min**. Runs on a background thread with progress and cancel. Reports inverted polarity, never flips it.
- JUCE options: `JUCE_WEB_BROWSER=0`, `JUCE_USE_CURL=0`.
- All code in namespace `aligna`.

**Plan decision (deviation in mechanism, not intent, from spec "Sample rate"):** instead of resampling each clip to the device rate, sources are resampled to the project rate once at import (in `SourcePool`). If the device rate differs from the project rate, the whole mix goes through one `juce::ResamplingAudioSource`. The stored model is still never rescaled.

## Review Focus

1. **File at a different sample rate than the project** (44.1 kHz file in a 48 kHz project): length and playback pitch must be correct. Test in Task 6.
2. **Project opened when an audio file has moved or been deleted**: the project still opens, the clip is silent and drawn as "missing", and there is no crash. Tests in Tasks 5 and 7.
3. **Moving or trimming a clip to before time 0, or trimming past the source's end**: clamped, never negative and never reading past the buffer. Test in Task 2.
4. **Auto-align on silence or unrelated audio**: no move happens without the user confirming, and silence returns an error rather than a random offset. Test in Task 11.
5. **Long sessions** (more than 2³¹ samples, about 12.4 h at 48 kHz): positions must not overflow in the model, mapping or JSON. Tests in Tasks 2, 5 and 9.

### Task 7: Mixer and WAV export

**Files:** Create `src/engine/Mixer.h/.cpp`, `tests/MixerTest.cpp`

**Interfaces:**
- Consumes: `Project`, `AudioData`, `SourcePool::get`.
- Produces:
  ```cpp
  struct MixSnapshot { Project project; std::map<juce::String, AudioData> audio; };  // built off the audio thread
  std::shared_ptr<const MixSnapshot> makeSnapshot(const Project&, const SourcePool&);
  // Adds (does not clear) numSamples of stereo mix starting at timeline pos `start` into out[ch][offset...]
  void renderMix(const MixSnapshot&, SamplePos start, juce::AudioBuffer<float>& out, int offset, int numSamples);
  bool exportMix(const MixSnapshot&, const juce::File& wav, int bitDepth, juce::String& error,
                 const std::function<bool(float)>& progress = {}); // renders [0, projectEnd), returns false if cancelled
  ```
  Rules:
  - Clip gain is in dB.
  - Fades are linear: fade-in ramps 0→1 over `fadeIn` samples, and fade-out works the same way at the end.
  - Track volume is in dB.
  - Pan for mono sources uses constant-power: `L = cos((pan+1)π/4)`, `R = sin((pan+1)π/4)`. For stereo sources pan is a balance: left gain `min(1, 1-pan)`, right gain `min(1, 1+pan)`.
  - Solo: if any track is soloed, only soloed tracks that aren't muted play.
  - Overlaps: the later-starting clip covers the earlier one, and if two clips start at the same position, the later one in the vector wins.
  - Missing sources are silent.
  - `renderMix` must not allocate. Pre-sort clips by start inside `makeSnapshot`.
- [ ] **Step 1:** Write tests. Use in-memory `AudioData` with constant values (e.g. all 0.5) so expected samples are exact.
  - A single mono clip at start 10 with value 0.5 and pan 0 gives silence before 10 and `0.5·cos(π/4)` after it, on both channels.
  - Overlap: clip A (value 0.25) covers [0,100), clip B (value 1.0) covers [50,150). Output[60] comes only from B, and output[40] comes only from A.
  - A gain of −6.0206 dB halves the output. A fade-in of 10 samples gives output at the clip's start = 0 and output at 5 = half.
  - Mute silences the track. Solo on track 2 silences track 1.
  - A block that straddles a clip boundary renders the same samples as two separate blocks.
  - Missing source: the project renders with no crash and the output is 0.
  - `exportMix` at 24-bit writes a file. Read back, its length equals `projectEnd` and its samples are within 1e-6 of `renderMix`.
- [ ] **Step 2:** Run the tests. Expected: FAIL.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** Run the tests. Expected: PASS.
- [ ] **Step 5:** Commit `feat: offline mixer and WAV export`.

### Task 11: Correlation and clip alignment (core)

**Files:** Create `src/align/Correlate.h/.cpp`, `src/align/AlignClips.h/.cpp`, `tests/AlignTest.cpp`

**Interfaces:**
- Produces:
  ```cpp
  struct OffsetResult { SamplePos lag; float confidence; bool polarityInverted; };
  // target[n] ≈ ±reference[n - lag]; search |lag| <= maxLag. progress(0..1) returns false to cancel.
  std::optional<OffsetResult> findOffset(const std::vector<float>& reference, const std::vector<float>& target,
                                         SamplePos maxLag, double sampleRate,
                                         const std::function<bool(float)>& progress, juce::String& error);
  struct ClipAlignment { SamplePos newStart; float confidence; bool polarityInverted; };
  std::optional<ClipAlignment> computeAlignment(const MixSnapshot&, const juce::String& referenceClipId,
        const juce::String& targetClipId, std::optional<juce::Range<SamplePos>> selection,
        double maxShiftSeconds, const std::function<bool(float)>& progress, juce::String& error);
  constexpr float kConfidentThreshold = 2.0f;
  ```
  The algorithm (not determined by the tests):
  1. **Coarse pass.** Decimate both signals to about 8 kHz: factor `d = max(1, floor(rate/8000))`, after a simple lowpass (moving average of length d). Run GCC-PHAT with `juce::dsp::FFT` (size = next power of two ≥ len_ref + len_tgt). This gives cross-spectrum `R = X·conj(Y) / max(|X·conj(Y)|, 1e-12)`, and the coarse lag is the peak of `|IFFT(R)|` within `±maxLag/d`.
  2. **Fine pass.** Refine at full rate with direct, normalised cross-correlation within `±2d` samples of `coarse·d`. Take the peak of the absolute value. `polarityInverted` is true when the correlation at the peak is negative.
  3. **Confidence.** Confidence = the PHAT peak divided by the largest PHAT value more than 5 ms away from it.
  4. **Errors.** Return an error if either signal's RMS is below 1e-5 ("Clip is silent in the compared region").

  `computeAlignment` works out the region and the new start:
  - **Region.** If there's a selection, the region is the selection intersected with the reference clip. Otherwise it is the reference clip's range intersected with the target clip's range widened by `maxShiftSeconds`, cut down to its first 60 s. An empty region gives the error "Clips are too far apart — increase the search range".
  - **Signals.** It renders the reference clip alone (mono, unity gain, no fades) over the region. It renders the target clip alone over the region widened by `maxLag` on both sides.
  - **New start.** `newStart = target.start - lag`, clamped to ≥ 0.
